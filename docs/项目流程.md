# 一、Agent 与千问模型的协作关系（不是完全调用，是基座 + 自主开发模块）

- 千问 Qwen 是唯一底层基座：所有智能体的语义理解、文献阅读、推理、文本生成能力必须依托阿里云百炼 API 调用千问开源系列（Max/Plus/Turbo 等），不能换其他大模型；可对千问做领域 SFT 微调，但模型本体仍是千问。

- 团队自主开发上层 Agent 模块：千问只提供基础大模型能力，多智能体 / 超级智能体的调度逻辑、数据处理流水线、领域专用工具、迭代校验、人在回路交互、前端可视化等全部为参赛团队自研模块，属于在千问之上搭建业务智能系统。

简单总结：千问做底层大模型能力底座，团队自主开发整套 Agent 架构与科研业务流水线，Agent 全程调用千问完成各类语义任务。

# 二、完整项目执行流程

## 阶段 1：前期准备（报名 + 资源申领）

- 团队在挑战杯官网完成赛事报名、盖章上传报名表；

- 申领阿里云算力补贴，开通百炼平台，获取千问模型 API 调用凭证；

- 确定赛道方向（自然科学 / 人文社科），选定细分研究领域，收集合规领域数据集、权威参考文献。

## 阶段 2：AI Scientist 多智能体 / 超级智能体架构开发（核心研发）

- 自研分层 Agent 流水线，每一步均调用千问执行语义任务，自研代码负责调度、清洗、校验、循环迭代：

- 文献挖掘 Agent：调用千问读取论文 / 领域数据，自研代码完成文本清洗、结构化抽取科学事实、过滤无效信息；

- 推理假设生成 Agent：输入提取事实，千问执行归纳 / 演绎推理产出初始科学假设，自研模块做逻辑自洽校验；

- 跨学科迭代论证 Agent：自研逻辑实现多轮循环，调用千问检索交叉领域文献，验证假设可行性、补充实验路径；

- 思辨人机交互 Agent（人在回路）：自研交互前端 / 接口，千问承接人工反馈，对假设、实验方案反复辩论优化；

- 标准化输出 Agent：自研格式化模块，调用千问按赛事规范生成完整《科学假设与研究计划》全套标准化字段内容。

## 阶段 3：模型优化与工程落地

- 用领域专属数据对千问开展监督微调 SFT，提升垂直科研领域适配度；

- 搭建可交互前端页面，制作 10 分钟内系统演示视频；

- 整理全部核心源代码，留存千问 API 调用截图、数据集来源、文献引用。
